01 · eBPF

eBPF 는 커널 안에 작은 프로그램을 끼워 넣는 기술입니다.

비유 :커널은 공항, Hook 은 검문소. 심사를 통과한 요원(프로그램)을 검문소에 세워 지나가는 패킷마다 확인하게 한다
커널 (Linux)
Cilium 이 프로그램 작성작은 C 코드 → 바이트코드로 컴파일
cilium-agent표를 갱신하고 프로그램을 교체
Verifier · 안전 심사무한루프 · 잘못된 메모리 접근이면 거부
Hook 에 장착패킷이 지날 때마다 실행 · 네이티브 속도(JIT)
Map · 조회표정책 · 서비스 · IP→번호 표. 커널과 Cilium 이 같이 읽고 쓴다
커널을 고치거나 재부팅하지 않는다. 심사를 통과한 코드만 커널 안에서 돌기 때문에 안전하고, 커널 안에서 돌기 때문에 빠르다
01 · Hook

패킷이 지나는 길에 검문소(Hook) 세 곳이 있습니다.

패킷 처리는 TC, 서비스 주소 변환은 socket, 외부 유입 가속은 XDP. 셋 다 iptables 보다 앞이라 체인을 탈 일이 없다
02 · Cilium 구조

Cilium 은 노드마다 Agent 하나가 eBPF 를 관리합니다.

kube-apiserverPod · 정책 · Identity 정보가 모이는 곳
cilium-operator · 클러스터 단위노드별 Pod IP 대역 배정 · 안 쓰는 Identity 정리
Node · 모든 노드에 똑같이 (DaemonSet)
cilium-agentapiserver 를 보고 있다가 eBPF 프로그램과 표를 갱신
cilium-cni컨테이너 런타임이 Pod 를 만들 때 호출 → agent 에 요청
Podeth0 ↔ 호스트 veth
eBPF 프로그램 + 표(Map)veth · eth0 · 터널 장치에 붙어서 패킷을 실제로 처리한다
제어는 Agent, 처리는 eBPF. 그래서 Agent 가 죽어도 패킷은 계속 흐른다. 새 Pod 와 정책 반영만 멈춘다

Pod A → Pod B, veth 에서 veth 로 넘어갑니다.

04 · kube-proxy 대체

서비스 주소 변환을 패킷이 생기기 전에 끝냅니다.

서비스 주소를 단 패킷이 아예 생기지 않으니 바꿀 규칙도 필요 없다. 그래서 kube-proxy 를 통째로 뗄 수 있다
05 · Identity

정책은 IP 가 아니라 사원증 번호(Identity)로 봅니다.

Identity :같은 라벨을 가진 Pod 들에 붙는 하나의 번호. Pod 가 늘거나 IP 가 바뀌어도 번호는 그대로
각 노드가 들고 있는 eBPF 표
Pod frontend-1app=frontend · 10.244.1.5
Pod frontend-2app=frontend · 10.244.2.9
Pod frontend-3app=frontend · 10.244.3.4
번호 42301라벨 app=frontend 에 붙은 사원증 번호 · 클러스터 공통
Pod 1,000 개여도 규칙 1 줄
IP 가 바뀌어도 번호는 그대로
표 (Map)IP → 번호 (모든 노드)
10.244.1.5 → 42301
10.244.2.9 → 42301
10.244.3.4 → 42301
허용 규칙 (backend 쪽 veth)
(42301, 8080) → 허용
Pod backendfrontend 를 받는 규칙은 한 줄
Calico 는 IP 목록으로 판정해 Pod 가 바뀌면 모든 노드의 목록을 고친다. Cilium 은 번호로 판정하니 정책 표는 그대로, IP→번호 한 줄만 더해진다
05 · 정책

정책은 양쪽 veth 에서 번호로 판정합니다.

포트까지는 표 조회로 끝. HTTP 경로처럼 내용을 봐야 하는 규칙이 있는 흐름만 Envoy 를 한 번 더 거친다
06 · Hubble

Hubble 은 모든 판정을 기록하는 블랙박스입니다.

Hubble :eBPF 가 패킷마다 남긴 기록(누가 → 누구에게 · 포트 · 통과/차단 · 이유)을 모아서 보여주는 도구
각 노드 안
eBPF 데이터패스통과 · 차단 · 이유를 그때그때 남김
Hubble 서버 (agent 안)번호 → Pod 이름 · 라벨로 바꿔 줌
기록 한 줄 예frontend-1 (42301) → backend-2 (50117) :8080 · DROPPED (Policy denied)
hubble-relay모든 노드의 기록을 한 곳에
hubble observeCLI · 차단된 것만 골라 보기
Hubble UI서비스 맵 · 누가 누구와 통신하나
메트릭Prometheus 가 긁어감 · 흐름 수 · 차단 수
차단되면 누가, 누구에게, 왜 가 한 줄로 나온다. 통신이 안 될 때 tcpdump 보다 먼저 hubble observe

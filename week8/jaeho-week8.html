Week 8 · Network Troubleshooting
00 · 문제 정의

먼저 노드와 Pod 의 구성, 그리고 네 가지 길을 봅니다.

ClusterIP 는 어느 노드에도 없다. 변환표 속 규칙일 뿐이고, 네 길은 결국 모두 ① Pod IP 길을 탄다
01 · 좁히는 순서

먼저 네 가지 질문으로 종류를 가릅니다.

처음 ✕ 가 나온 질문이 장애의 종류다. 이름으로 안 된다고 DNS 부터 보지 않는다
01 · Pod-to-Pod

Pod IP 로 안 되면 길을 반으로 잘라 갑니다.

첫 tcpdump 는 받는 노드에서 뜬다. 한 번에 길의 절반이 사라진다
01 · Pod-to-Service

ClusterIP 는 유령 주소, 실체는 변환 표입니다.

Service 장애의 절반은 이 표가 비어 있는 것이다. iptables 보다 get endpoints 가 먼저다
01 · External

바깥과 통하려면 노드가 봉투의 주소를 고쳐 씁니다.

나가는 쪽은 src 가 노드 IP 로 바뀌었는지, 들어오는 쪽은 봉투가 노드까지 왔는지부터 본다
02 · CNI 장애

CNI 가 넘어지면 Events 의 마지막 줄을 읽습니다.

$ kubectl describe pod web-7d9f -n app

Node: worker-3/192.168.0.13

Status: Pending

State: Waiting · ContainerCreating

…

Events:

Warning FailedCreatePodSandBox kubelet

failed to setup network for sandbox "3fa2…":

plugin type="calico" failed (add):

connection is unauthorized: Unauthorized

1ContainerCreating = 네트워크 단계

이미지·스케줄링 문제는 다른 상태다. Events 에 FailedMount 가 없으면 CNI 가 끝나야 열리는 단계

2FailedCreatePodSandBox = CNI ADD 실패

Week 4 의 ADD 호출이 실패했다. 원인은 뒤쪽에 붙어 있다

3plugin type= 이 범인

calico · flannel · multus · macvlan. multus 면 NAD 이름 오타부터 (Week 6)

4마지막 줄이 이유

Unauthorized 토큰 만료 · no IP addresses IPAM · no such file 바이너리 없음

"plugin type=" 뒤가 범인, 그 뒤 문장이 이유다. 노드 로그는 그 다음이다
02 · CNI 점검

노드 안에서 파일 둘과 데몬 하나를 차례로 봅니다.

설정 → 바이너리 → 데몬 순서. DaemonSet 이 멀쩡해 보여도 그 노드에는 Pod 가 없을 수 있다
03 · IPAM

같은 /16 이라도 쪼개는 모양이 세 가지입니다.

IPAM :Pod 에 줄 IP 를 어느 대역에서 누가 꺼내 주나. 셋 다 비면 같은 메시지 — "no IP addresses available"
같은 에러 메시지라도 host-local 은 노드 한 대, calico-ipam 은 Pool 전체, whereabouts 는 범위 전체가 빈 것이다
03 · IP Pool

IP Pool 장애는 네 가지 모양입니다.

소진인지 누수인지는 할당 수와 실제 Pod 수의 막대 길이를 비교하면 바로 갈린다
04 · Routing

라우팅 장애는 경로 표 한 줄이 없거나 엉뚱합니다.

ip route get 이 고른 장치가 틀리면 경로 문제, 맞는데 안 가면 MTU 나 방화벽이다
04 · NetworkPolicy

정책은 담장이고, 적어 둔 방향만 문이 열립니다.

1위는 egress 에 DNS 53 을 안 연 것. 담장을 세운 Pod 는 이름 풀이부터 막힌다
04 · DNS

이름 하나에 질의가 네 번 나갑니다.

nslookup kubernetes.default 가 되면 ①② 는 통과. 남는 건 느림(ndots)과 밖(upstream) 둘뿐이다
04 · kube-proxy

kube-proxy 장애는 없는 규칙과 낡은 규칙입니다.

KUBE-SVC 체인이 없다고 고장은 아니다. 먼저 누가 변환을 맡는지부터 확인한다
Q&Atcpdumpendpointsip routenslookup
